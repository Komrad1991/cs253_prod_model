# ============================================================================
#  Демонстрация №2: правило, пригодное для прямого вывода, но не для обратного.
#
#  Правило UNSAFE_TANK_NEED содержит переменную ?h, которой нет в заключении
#  (экзистенциальная переменная). Прямой вывод такие правила выполняет: он
#  перебирает факты и находит ?h = Abrams. Обратному выводу не с чем связать
#  ?h — цель need(anti_tank) не содержит героя, поэтому ветвь отсекается.
#
#  Это ограничение не движка, а самого способа записи правила: чтобы правило
#  работало в обе стороны, его переписывают в «безопасной» форме — либо
#  добавляют героя в заключение, либо размножают правило по героям (так
#  сделано в основной базе: THR_ABRAMS_TANK_FRONTLINE и т.п.).
#
#  Запуск:  pmcli run --kb data/demo_unsafe_rule.txt --mode both
# ============================================================================
kb "Демонстрация: небезопасное правило"
description "Прямой вывод доказывает цель, обратный — нет; причина в экзистенциальной переменной."

fact enemy(Abrams)
fact hero_role(Abrams, tank)

rule UNSAFE_TANK_NEED cf=0.90
  if enemy(?h) and hero_role(?h, tank)
  then need(anti_tank)
  why "Против танка нужна защита от танка (?h не входит в заключение)."

goal need(anti_tank)
